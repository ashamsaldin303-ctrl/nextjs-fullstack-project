# برومبت البناء الرابع — المرحلة 4: ثورة الواجهة الحسّية (من Launch-Ready إلى Wow)

## 0) قبل أي شيء
اقرأ دليلك `FULLSTACK_AGENT_GUIDE.md` من أوله إلى آخره والتزم بكل ما فيه. هذا برومبت **مرحلة رابعة فوق كود قائم وعامل** — وليس مشروعاً جديداً. القاعدة الذهبية لهذه المرحلة: **لا تكسر شيئاً يعمل**. كل ما بُني في المراحل 1–3 والهوتفكس يجب أن يظل يعمل بعد تسليمك كما هو: المحاكي الحي، الحاسبة مع إرسالها الآمن كاملاً، المؤشر المغناطيسي، Audio UX، الحبيبات السينمائية، hreflang، الويبهوك الموقّع HMAC.

## 1) سياق الحالة الراهنة (اعرف ما الذي تعمل فوقه)
- المراحل المسلّمة: `b2cf261` (التأسيس + الرئيسية والصفحات) → `1a3c7ae` (الطبقة الحسية: المؤشر المغناطيسي، Grain، Audio UX، إثراء المحتوى، reactCompiler، hreflang) → `dd1c3ce` (الخلفية: POST /api/leads بـ Zod صارم، حساب الميزانية على السيرفر، Rate limiting، ويبهوك HMAC إلى n8n، Dockerfile) → `3a2bbd5` (هوتفكس 01: fallback ‏100svh، ‏env.example، توثيق مسار قاعدة البيانات، التحميل الكسول للمحاكي). الموقع معلن **Launch-Ready**.
- حالة الأداء — خط الأساس الذي **يُمنع التراجع عنه**: CLS = 0، وa11y/best-practices/SEO = 100، وperf: الرئيسية 68–76 و/work = 97. سبب ضعف الرئيسية: كتلة JS الأولية للشاشة الأولى — وقد عُولج جزئياً بجعل **أول رسم للهيرو CSS-only. هذا القرار مقدَّس ولن يُنقض**.
- مراجعة بصرية مستقلة (25 لقطة × تحليل آلي): 8.3/10 إجمالاً. أقوى ما لدينا: الهوية اللونية 9/10، شبكة Bento التفاعلية، جودة RTL. أضعف ما لدينا (سيصلحها هذا البرومبت أولاً): الحاوية الضيقة على الشاشات العريضة (أعلى الملاحظات تكراراً)، تباين النصوص الثانوية على الداكن، تفاصيل التايبوغرافي العربي، عمق البطاقات، حالة روابط قائمة الجوال.

## 2) قرار المراجعة على مقترحات صاحب المشروع (A–E) — ملزم

| المقترح | القرار | الخلاصة |
|---|---|---|
| A. هيرو «وحدة تحكم الأتمتة التفاعلية» | ✅ مقبول بتعديل جوهري | شريط الأوامر HTML/CSS فوري في المسار الحرج، ومشهد WebGL لا يُركَّب إلا **بعد تفاعل المستخدم** — حمايةً لـ LCP |
| B. العرض المفكّك المثبّت بالتمرير | ⚠️ مبسّط | نسخة واحدة مميزة بـ CSS 3D + sticky فقط — لا WebGL ولا اختطاف تمرير |
| C. المؤشر السياقي الفيزيائي | ✅ مقبول كما هو | امتداد رخيص للمؤشر المغناطيسي القائم (سمة data-cursor + شريحة نصية مترجمة) |
| D. الداكن الفاخر #08080A + الضوء الكاشف | ✅ مقبول بتعديل | توكن جديد للأقسام الغامرة + Spotlight بـ CSS خالص — **ويُرفض جزء تشويه GLSL** لمنزلق قبل/بعد |
| E. عدادات الحاسبة الحلقية | ✅ مقبول كما هو | SVG خالص + تحريك stroke-dashoffset — لا Canvas ولا WebGL |
| إضافة خط Geist | ❌ مرفوض | Inter + Cairo يكفيان (متغيّران ومحمّلان أصلاً)؛ خط ثالث = وزن بلا قيمة |

القاعدة الحاكمة من المراجعة: كل ما هو «جميل لكنه يهدد LCP أو الوصولية أو الجوال» يُنفَّذ بنمط **«CSS أولاً، ثم WebGL عند التفاعل»** أو يُؤجَّل. إن تعارض أي «wow» مع خط أحمر من القسم 9: الخط الأحمر يفوز دائماً.

## 3) خط العمل 0 — إصلاحات المراجعة البصرية P0/P1 (نفّذها أولاً، قبل أي إضافة جديدة)
1. **نظام الحاوية سريع الاستجابة** (أعلى ملاحظة تكراراً): أنشئ توكن/مكوّن حاوية موحّداً يُستخدم في كل الأقسام والصفحات عبر تعريف واحد (ممنوع التعديل اليدوي قسمًا قسمًا): عرض أقصى 1152px أساساً → 1280px عند ≥1280 → 1440px عند ≥1536 → 1568px عند ≥1920، مع padding جانبي سيّال (24/40/64px).
2. **تدقيق التباين على الداكن**: كل نص ثانوي فوق أي خلفية داكنة يجب أن يبلغ ≥ 4.5:1 ‏(AA). ارفع أي استخدام يعادل slate-500 إلى ما يعادل `#A3AEC2` فأعلى، وسلّم في تقريرك **جدول تدقيق** (العنصر / اللون / النسبة) لكل الخلفيات الداكنة القديمة والجديدة.
3. **تايبوغرافي عربي دقيق**: line-height عربي 1.75–1.85 للنص (اللاتيني يبقى 1.6)، قيد طول السطر (~65–70ch للاتيني وما يعادله ~40rem للعربي)، وletter-spacing = 0 دائماً للعربي (ممنوع tracking على نص عربي أبداً)، عناوين Cairo بوزن 700–900 وارتفاع سطر 1.25.
4. **عمق البطاقات**: حدود شفافة بيضاء 8–10% فوق الداكن + ظل ناعم متعدد الطبقات + خط إضاءة علوي 1px — كلها كتوكنز قابلة لإعادة الاستخدام، بلا أي تأثير على الوصولية.
5. **قائمة الجوال**: حالة نشطة واضحة للرابط الحالي (شريط سفلي بلون primary أو توهج) — أثناءها القائمة مفتوحة.

## 4) خط العمل 1 — هيرو «وحدة تحكم الأتمتة التفاعلية» (مقترح A معدَّلاً)
الفكرة: الهيرو يتحول من «إعلان» إلى «تجربة» — الزائر يختار ما يريده فتُبنى منظومته أمام عينيه.
- **الطبقة الفورية (CSS-only، تحمي LCP)**: العنوان الرئيسي والـ CTA و**شريط الأوامر** (واجهة HTML/CSS خفيفة) يُرسمون فوراً كما اليوم. شريط الأوامر: حقل إدخال + 4 رقائق Preset: «متجر ذكي + n8n» · «منصة حجوزات» · «وكيل AI لخدمة العملاء» · «لوحة تحكم تحليلية». النص الحر الذي لا يطابق Preset يفتح مشهداً عاماً «منظومة مخصصة» + سطر «سنتواصل معك لنصممها معك».
- **طبقة التفاعل (WebGL عند الطلب فقط)**: عند اختيار Preset أو Enter: يُركَّب مشهد R3F (dynamic import بـ ssr:false — يُلَمَّح الـ chunk بعد requestIdleCallback فور تحميل الصفحة، لكن **لا يُرسم قبل التفاعل أبداً**): عقد 3D متوهجة تتجمع + وصلات ضوئية ترسم معمارية المنظومة المختارة، نبض خفيف، انجراف كاميرا بطيء. أعد استخدام three.js/R3F الموجودين في المشروع — **ممنوع إضافة مكتبات 3D جديدة**.
- **تفاعل المشهد**: قابل للتدوير بالسحب (أفقي/رأسي بحدود clamp)، **عجلة الماوس لا تزوّم ولا تختطف التمرير**، والمؤشر السياقي (خط العمل 2) يظهر فوقه «اسحب للتدوير 360°».
- **التايبوغرافي الحركي بسرعة الماوس**: وزن خط العنوان المتغير يستجيب لسرعة المؤشر (متغير CSS + rAF مقيّد بمدى صغير wght 600→800، على مستوى الكلمات للعربي).
- **الجوال (<768px)**: شريط الأوامر يعمل كاملاً، لكن بدل WebGL يُعرض مخطط عقد SVG متحرك بلغة المحاكي البصرية ذاتها (تفكيك تدريجي للعقد والوصلات).
- **reduced-motion**: مخطط ثابت + شرح نصي للمعمارية. **فشل إنشاء WebGL**: اكتشاف القدرة ثم fallback تلقائي إلى نسخة SVG نفسها.
- **الصوت**: أصوات Web Audio خفيفة عند «إقلاع» الكونسول عبر النظام الصوتي القائم (مطفأة افتراضياً كما هي).

## 5) خط العمل 2 — المؤشر السياقي (مقترح C — امتداد للمغناطيسي القائم)
- العناصر التفاعلية تعلن نفسها بـ `data-cursor="rotate | preview | drag | compare | …"` والمؤشر المغناطيسي الحالي يعرض **شريحة نصية مترجمة** بجانب الحلقة حسب السياق: «اسحب للتدوير 360°» فوق مشاهد 3D، «معاينة حية» فوق بطاقات الأعمال، «اسحب للمقارنة» فوق منزلق قبل/بعد.
- نطاق المغنطة حول الأزرار الرئيسية 30px بحركة spring ناعمة (كما طلب صاحب المشروع).
- كل شروط التعطيل القائمة تبقى: أجهزة اللمس، المؤشر الخشن، prefers-reduced-motion.
- **زر الصوت في الأعلى**: انقل/أبرز زر تبديل الصوت الموجود (من المرحلة 2) إلى الـ Navbar بوضوح، مع aria-label مترجم — بلا أي منطق جديد.

## 6) خط العمل 3 — القاعدة الداكنة الفاخرة + الضوء الكاشف (مقترح D معدَّلاً)
- توكن جديد `background-deep: #08080A` للأقسام **الغامرة فقط** (هيرو الكونسول، المحاكي، الشهادات)؛ و`#0F172A` يبقى للأشرطة الداكنة الاعتيادية — نظام داكن ثنائي العمق مقصود. الحبيبات القائمة تبقى وترتفع شفافيتها قليلاً فوق Deep فقط.
- **الضوء الكاشف**: طبقة تتبع الماوس (radial-gradient بقطر ~700px عبر `--mx/--my`) تكشف **شبكة Blueprint خفيفة** (خطوط CSS grid بشفافية 4–6%) تحت الأقسام Deep — ‏pointer-events: none، حركة عبر transform فقط، وتعطيل على اللمس (شبكة ثابتة خفيفة أو لا شيء) ومع reduced-motion.
- **المرفوض صراحةً من هذا المقترح**: تشويه GLSL السائل لمنزلق قبل/بعد — يبقى clip-path الحالي (وصولية كاملة بلوحة المفاتيح وخفة). إن أردت لمسة: اكتفِ بمعالجة SVG خفيفة على مقبض المنزلق فقط.

## 7) خط العمل 4 — عدادات الحاسبة الحلقية (مقترح E)
- في خطوة النتيجة من المعالج: حلقتان SVG متحركتان (نطاق الميزانية + المدة بالأسابيع) بتحريك stroke-dashoffset عند الظهور وعند كل تغيير قيمة، والأرقام تعدّ تصاعدياً بتنسيق الأرقام المتبع في الموقع.
- SVG خالص (لا Canvas ولا WebGL)، متطابقتان بصرياً في RTL/LTR مع عكس اتجاه الدوران في RTL، وreduced-motion: قيم فورية بلا تحريك.

## 8) خط العمل 5 — بطاقة العمل المفكّكة (مقترح B مبسَّطاً وآمناً)
- مشروع مميز واحد (أول بطاقات الأعمال المختارة): عند دخوله منطقة sticky يتفكك إلى **ثلاث طبقات فضائية بـ CSS 3D فقط** (transform: translateZ/rotateX/rotateY): طبقة الواجهة الزجاجية (إطار متصفح) ← طبقة الأنظمة (عقد n8n ووصلات بلغة المحاكي البصرية) ← طبقة النتائج (شرائح أرقام). تقدم التمرير يقود التباعد (useScroll أو CSS scroll-timeline).
- ممنوع: WebGL، اختطاف التمرير (التمرير الطبيعي سليم دائماً)، تثبيت يمتد أكثر من شاشة واحدة.
- <768px: تكوين ثابت متراكب أنيق. prefers-reduced-motion: العرض النهائي المركّب ثابتاً.

## 9) الخطوط الحمراء للأداء (غير قابلة للتفاوض)
1. **LCP محمي**: أول رسم للهيرو CSS خالص؛ أي مكتبة 3D خارج المسار الحرج — WebGL يُركَّب **بعد تفاعل المستخدم فقط**.
2. JS المبدئي للأقسام الساكنة < 200KB — كل جديد ثقيل dynamic بـ ssr:false.
3. <768px: **صفر WebGL في كامل الموقع** — بدائل CSS/SVG مكافئة بصرياً.
4. 60FPS: DPR ≤ 2، إيقاف الرندر خارج الشاشة (IntersectionObserver) وعند إخفاء التبويب، تحريك transform/opacity فقط، مستمعات passive.
5. Lighthouse: a11y/bp/seo تبقى 100، وperf **لا يتراجع** عن خط الأساس — والهدف رفع الرئيسية من 68–76 نحو 85+ (تقليص JS الشاشة الأولى فرصة ذهبية هنا).
6. prefers-reduced-motion: بديل راقٍ لكل ميزة جديدة بلا استثناء.
7. اكتشاف فشل WebGL + fallback دائماً (نسخة SVG المكافئة).
8. **الخلفية لا تُلمس**: Leads/API/الويبهوك/Rate limiting خارج نطاق هذه المرحلة؛ أي تعديل اضطراري يوثَّق ويُختبر تراجعياً.

## 10) تكافؤ RTL/LTR
- كل الجديد بخصائص CSS منطقية فقط (ms/me/ps/pe/start/end) — كالقاعدة القائمة.
- شريحة المؤشر السياقي تنعكس جانبياً في RTL، حلقات الحاسبة تعكس اتجاه الدوران، وطبقات التفكيك تنعكس بترتيب صحيح.
- كل مفاتيح الترجمة الجديدة في ar.json وen.json بتكافؤ 100% (سكربت الفحص يمر).
- الخطوط: Inter + Cairo فقط (قرار مراجعة: لا Geist).

## 11) تعريف «الاكتمال» (وليس it compiles)
- lint + tsc + سكربت تكافؤ i18n = صفر أخطاء.
- **تقرير أداء قبل/بعد**: Lighthouse ‏(perf/a11y/bp/seo) للرئيسية وكل المسارات + حجم JS المبدئي قبل/بعد.
- جدول تدقيق التباين للنصوص الثانوية على كل الخلفيات الداكنة.
- تحقق يدوي موثق: AR/EN × ‏PC/Mobile × مع/بدون reduced-motion — الكونسول، المؤشر السياقي، الضوء الكاشف، العدادات الحلقية، البطاقة المفككة تعمل، **وكل ميزات المراحل 1–3 تعمل (محاكي، حاسبة بإرسال كامل حتى الويبهوك، صوت، مؤشر، قبل/بعد)**.
- المتصفح نظيف: لا أخطاء console ولا تحذيرات hydration.

## 12) ترتيب التنفيذ والتسليم
نفّذ بالترتيب، وكل خط عمل commit مستقل قابل للمراجعة:
**WS-0** (إصلاحات المراجعة) → **WS-3** (التوكنز الداكنة + الضوء الكاشف) → **WS-1** (كونسول الهيرو) → **WS-2** (المؤشر السياقي + زر الصوت) → **WS-4** (العدادات الحلقية) → **WS-5** (البطاقة المفككة).
بعد التسليم: تقرير موجز (ما بُني، القرارات المتخذة وأسبابها — خاصة تعديلاتي على مقترحات A وB وD، أرقام الأداء، توصياتك للمرحلة 5).

## 13) تعليمات التنفيذ
- ابدأ الآن بـ WS-0 وسلّم المرحلة كاملة.
- لا تخترع ميزات أو صفحات خارج نطاق هذا البرومبت.
- عند قرار معماري غير محسوم: اختر الأبسط ووثّق قرارك بسطر في README.
- لا مكتبات جديدة إلا بمبرر قوي موثق — لديك framer-motion وR3F وSVG كافية.
