# قوائم الفحص المجمّعة — بوابة الإطلاق والتحقق

> **الاستخدام:** هذه هي "طبقة التحقق" للحزمة. أي وكيل ينتهي من مهمة (بناء/تحسين/إصلاح) يجب أن يمرر عمله على القوائم هنا ويصلح قبل إعلان الإنجاز. كل بند بإحالة لمصدره (تقرير 1-x، النتيجة N).

---

## 1) تعريف النجاح النهائي (Definition of Done)

**الأداء — كلها إلزامية:**
- [ ] Lighthouse 90+ على الجوال (تقرير 1-a، النتيجة 16)
- [ ] LCP < 1.5s — CLS < 0.05 — INP < 100ms
- [ ] أول JS ≤ 90KB مضغوط gz — الصفحة < 3MB
- [ ] 60fps ثابتة (لا jank عند السكرول/الحركة)

**الديزاين:**
- [ ] تقييم ذاتي ≥ 8/10 على المعايير الأربعة (Design/Usability/Creativity/Content) **لكل صفحة** لا الرئيسية فقط (تقرير 1-a، النتيجة 17)
- [ ] لحظة توقيع واحدة — وكل مؤثر منافس حُذف (1-a، 13)
- [ ] نظام تصميم واحد متسق عبر كل الصفحات (1-a، 62)

**الحركة:**
- [ ] منحنى easing واحد في كل مكان (1-g، 5)
- [ ] 0 أنيميشنات layout — transform/opacity حصراً (1-i، 62)
- [ ] نسخة reduced-motion مكدّسة كاملة (استبدال لا حذف)

**الوصولية:**
- [ ] contrast ≥ 4.5:1 — focus مرئي — WCAG AA (1-h، 35؛ 1-g، 69)
- [ ] `prefers-reduced-motion` على كل مؤثر + `:focus-visible` بنبضة 180ms

**الـ Slop:**
- [ ] Anti-Slop Audit (قائمة 2 أدناه) = أقل من 3 "نعم" (1-e، 87)

**الجوال:**
- [ ] مختبر فعلياً على أندرويد متوسط + آيفون بشبكة throttled 4x (1-b، 92)
- [ ] صُمم عند 375px أولاً — ليس نسخة مصغّرة من الديسكتوب (1-a، 59)

## 2) Anti-Slop Audit — 20 بنداً قبل أي نشر (3+ "نعم" = إرجاع تلقائي)

> تجميع من 16 نمطاً + tells البصرية + علامات النص + محظورات الكود (تقرير 1-e، النتيجة 87)

**اللون:**
- [ ] هل يوجد تدرج بنفسجي-أزرق في أي مكان؟
- [ ] هل يستخدم indigo/slate/افتراضيات Tailwind بلا تعديل hue؟

**الخط:**
- [ ] هل Inter/Roboto/Arial هو "خط الهوية" (وليس خط نظام ثانوي)؟

**البنية:**
- [ ] هل الصفحة "badge مركزي + عنوان + 3 بطاقات"؟
- [ ] هل البنية النمطية Hero-Features-Testimonials؟
- [ ] هل dashboard بإحصاءات/شهادات مزيفة؟

**التفاصيل:**
- [ ] هل border-radius موحد في كل العناصر (بدل نظام قيمتين + استثناء)؟
- [ ] هل الظلال موحدة/افتراضية (بدل ظلين متراكبين hue-shifted)؟

**المحتوى:**
- [ ] نصوص من نوع "Empower your workflow"؟
- [ ] شهادات عامة "Sarah M., PM"؟
- [ ] lorem ipsum أو ترجمة آلية ظاهرة؟

**الصور:**
- [ ] وجوه AI مبتسمة / صور stock غير معالجة؟

**الحركة:**
- [ ] fadeIn متتالٍ متطابق على كل العناصر؟
- [ ] glassmorphism/glow زخرفي بلا وظيفة؟

**النص:**
- [ ] كلمات محظورة: delve, underscore, showcase, harness, leverage, seamless, robust, comprehensive, elevate, unlock, game-changer؟
- [ ] em dashes مفرطة + جمل متساوية الطول (صوت مسطّح)؟

**الكود:**
- [ ] hardcoded secrets / مفاتيح في المتغيرات؟
- [ ] dependencies غير متحقق منها (slopsquatting)؟

**سكربت CI المقترح (بوابة آلية):**
```bash
rg -i "from-(purple|violet|indigo|fuchsia)-" app components && echo "SLOP: purple gradient" && exit 1
rg -i "rounded-(2xl|3xl)" --glob '!**/tokens*' app | wc -l   # عدّ القيم خارج النظام
rg -i "shadow-(sm|md|lg|xl)" app | wc -l                   # الظلال خارج الـ tokens
rg "font-family.*inter" app | wc -l                        # Inter كخط هوية
```
(تقرير 1-h، النتيجة 67 — يُربط في CI + يُنسخ كقواعد توليد في CLAUDE.md)

## 3) قائمة فحص ما قبل التقديم للجوائز — "قابل للفوز"

> (تجميع نتائج 1-a / 1-j — قيّم كل صفحة على المعايير الأربعة من 10، وأصلح أدنى الصفحات أولاً)

1. [ ] نظام تايبوغرافي واحد متسق عبر كل breakpoints (scale + rhythm + hierarchy)؟ (1-a، 10)
2. [ ] الجوال تجربة مصممة بلمسات بديلة عن hover — لا نسخة مصغّرة؟ (1-a، 18)
3. [ ] LCP < 1.5s و CLS < 0.05 و60fps على أندرويد متوسط؟ (1-a، 16)
4. [ ] design system يصمد عبر كل صفحة؟ (1-a، 62)
5. [ ] لحظة توقيع واحدة — وكل مؤثر منافس حُذف؟ (1-a، 13)
6. [ ] المحتوى حقيقي 100% (لا lorem، لا ترجمة آلية، لا صور AI ظاهرة)؟ (1-a، 9)
7. [ ] hover state بـ easing مخصص لكل عنصر تفاعلي؟ (1-a، 15)
8. [ ] صفحات الخطأ والحالات الفارغة مصممة بجمال (error.tsx/not-found.tsx)؟ (1-a، 60)
9. [ ] لا popups/إعلانات/hard sell في أي مكان؟ (1-a، 63)
10. [ ] آخر أسبوعين صقل حقيقي (توقيت الحركات + حالات الأجهزة الشاذة)؟ (1-j، 8)
11. [ ] مرّ 2–4 أسابيع على الإطلاق لإصلاح edge cases قبل التقديم؟ (1-j، 12)
12. [ ] نص التقديم مكتوب كقصة قرار (challenge → 3 قرارات → نتيجة)؟ (1-a، 92)

**استراتيجية التقديم المتدرج:** soft launch → إصلاح → انتظار 2–4 أسابيع → **CSSDA أولاً** ($50) → Awwwards ($65–75) → FWA. التوقيت الأمثل: الاثنين/الثلاثاء في فبراير–أبريل أو سبتمبر–نوفمبر؛ تجنّب ديسمبر/يناير ويوليو/أغسطس (1-a، 3-4؛ 1-j، 67).

## 4) الأخطاء العشرة القاتلة (كلها موثقة — لا تقع فيها)

1. البدء بالـ hero المبهج قبل الاستراتيجية وwireframes (1-j، 22)
2. نشر كود AI بلا مراجعة/فحص أمني — 62% منها يحمل ثغرات حرجة (1-e، 55)
3. مطالبة الوكيل "اجعلها أجمل" بدل التوجيه بالعنصر والخاصية + screenshot (1-d، 42)
4. توزيع WebGL على الموقع كله بدل لحظة واحدة (1-j، 99)
5. `scrub: true` + `ease` غير none داخل scrubbed tweens (1-b، 3/94)
6. letter-spacing على العربية أو تقسيم النص بالحروف — نص مكسور (1-f، 65/27)
7. ضغط أسبوعي الصقل — "rushing kills award chances" (1-j، 8)
8. إطلاق وتقديم للجوائز في نفس الأسبوع (1-j، 12)
9. ترك فراغات للـ AI يملأها (خط/ألوان/نبرة غير محددة) (1-e، 82)
10. تعطيل السكرول لفرض قصة طويلة — scrolljacking (1-b، 96)

## 5) جدول القواعد الذهبية — اللاتيني مقابل العربي RTL

| البند | اللاتيني | العربية RTL | الإحالة |
|---|---|---|---|
| line-height للنص | 1.4–1.5 | **1.7–2.0** (مدود + نقاط + تشكيل) | 1-f/62 |
| line-height للعناوين | 0.95–1.1 | **1.3–1.45** | 1-f/62 |
| letter-spacing للعناوين | −0.02em (يشدّ) | **محظور** — يكسر اتصال الحروف (حارس CSS إلزامي) | 1-f/65, 73 |
| labels الصغيرة | uppercase + tracking واسع | وزن 600 + **word-spacing 0.3em** + لون accent | 1-f/66 |
| split-text | chars/words/lines | **بالكلمات أو الأسطر فقط** | 1-f/27 |
| stagger بين الوحدات | 30–60ms | **60–90ms** (إيقاع صرفي أطول) | 1-f/22 |
| مدد الحركة | الأساس | **أطول 20–30%** | 1-f/22 |
| justify | مقبول مع hyphenation | المسافات فقط — الأفضل `text-align: start` | 1-f/64 |
| الأرقام | tabular-nums | تبقى **LTR** معزولة + tabular-nums؛ سياسة واحدة | 1-f/67, 92 |
| خلط اللغات | — | خط ثنائي (IBM Plex Sans Arabic) أو size-adjust يدوي + عزل `<bdi>` | 1-f/57-60 |
| marquee التحريري | translateX(-100%) | **translateX(100%)** (معكوس مع اتجاه القراءة) | 1-f/24 |
| عناصر الاتجاه | — | اعكس ما له معنى اتجاهي (أسهم/progress/timeline)؛ الشعارات والأرقام ثابتة | 1-f/55, 61 |

## 6) مرجع نظام التوقيت الحركي (يلصق في globals.css)

```css
:root {
  --ease-out-expo: cubic-bezier(0.16, 1, 0.3, 1);   /* المنحنى الواحد في كل مكان */
  --ease-curtain: cubic-bezier(0.77, 0, 0.175, 1);  /* كشف الصور/الستائر */
  --dur-fast: 180ms;
  --dur-base: 280ms;
  --dur-slow: 480ms;
}
/* الاستثناءات الموثقة فقط: linear للتلاشي والحلقات،
   ease-in-out للسكون→السكون، spring (stiffness/damping) للسحب */
```
- كل tween مقيّد بالسكرول: `scrub: 1` + `ease: 'none'` + `anticipatePin: 1` (1-b، 3/94)
- Lenis + GSAP: `lenis.on('scroll', ScrollTrigger.update)` + `gsap.ticker.add((t)=>lenis.raf(t*1000))` + `gsap.ticker.lagSmoothing(0)` (1-b، 31)
- نوابض UI: tooltip (400, 30) / modal (200, 22) / draggable (300, 18) (1-g، 42–46)
- الفاخر = أبطأ 10–15% من السريع (مبدأ Timing من ديزني) (1-g، 79)

## 8) فحص الوكالة قبل التعاقد (لسيناريو استئجار فريق)

**اسأل دائماً (تقرير 1-j، النتيجة 37):**
1. هل أرى تفصيلاً مرحلياً للميزانية والنطاق؟ (بنود غامضة = تسعير لاحق)
2. من في فريق المشروع — in-house أم مقاولون؟
3. ما عملية ترحيل المحتوى (content migration)؟
4. ما التكاليف الجارية بعد الإطلاق (hosting/صيانة/رخص)؟
5. هل هناك مرحلة discovery؟ (غيابها = تخمين)
6. ما benchmarks الأداء الملتزمة (LCP/CLS/60fps)؟
7. تجربة الجوائز السابقة إن كان الطموح تقديماً؟

**Red flags:** لا benchmarks أداء في العرض • نهج template • جدول < 8 أسابيع لتفاعلات معقدة • "30 صفحة في 4 أسابيع" • "responsive" فقط دون تصميم جوال مخصص • أرخص عرض بفارق كبير (scope مفقود أو جودة مقطوعة) (1-j، 2؛ 1-a، 91)

## 9) قاعدة الصقل الختامية

> **آخر 3 أسابيع = الفرق بين درجة 6.2 ودرجة 7.5** (تقرير 1-j، النتيجة 8) — أسبوعان محميان للصقل حصراً: توقيت كل حركة، حالات التحميل، الشاشات الغريبة (320–414px)، focus states، رسائل الأخطاء. لا تضغطها مهما كان الضغط.

**تدقيق الاتساق النهائي:** زر واحد لكل دور — ظل واحد لكل ارتفاع — easing واحد لكل مدة؛ كل أيقونة موجودة، كل bullet يظهر، كل رابط داخلي يعمل (1-j، 82؛ 1-a، 48).
