## 4) منظومة سكرول أنيميشنز سينمائية

**ملفات:** `AGENT-INSTRUCTIONS.md` + `02-scroll-animations.md` + `09-animation-stack-performance.md` (لقرار الأداة)

```
أضف إلى موقعي [المكدس: Next.js/React/...] منظومة سكرول أنيميشنز بمستوى المواقع الفائزة
وفقاً لتقرير السكرول المرفق، بهذا الترتيب:

1. SmoothScrollProvider واحد بتركيب Lenis + GSAP "الساعة الواحدة":
   lenis.on('scroll', ScrollTrigger.update) + gsap.ticker.add((t)=>lenis.raf(t*1000))
   + gsap.ticker.lagSmoothing(0) + html { scroll-behavior: auto !important }
   بإعدادات lerp 0.07–0.1, wheelMultiplier 1.2.
2. قواعد scrub الثلاثة في كل مشهد: scrub: 1 + ease: 'none' + anticipatePin: 1.
3. الحركات الأساسية الموحدة: line-mask SplitText (بالكلمات عربياً!) + clip-path curtain reveal
   للصور + ScrollTrigger.batch للشبكات (stagger 0.08, expo.out, overwrite: true).
4. [اختر إن أردت]: قسم أفقي واحد (pin + scrub + xPercent عبر 4 panels مع containerAnimation)
   أو شريط تقدم قراءة CSS animation-timeline: scroll() خلف @supports.
5. تحقق من الأخطاء القاتلة الخمسة في التقرير (النتائج 7–12) بعد التنفيذ مباشرة.
6. نسخة prefers-reduced-motion: أقسام مكدّسة بحالات نهائية صحيحة (استبدال لا حذف).

الأقسام ذات الأولوية: [اذكرها]. لا scrolljacking: pinning قصير عالي القيمة تحت الطية فقط.
```

## 5) لحظة توقيع WebGL (خلفية توليدية / جسيمات)

**ملفات:** `AGENT-INSTRUCTIONS.md` + `03-webgl-generative-backgrounds.md` + الفصل 3 من `MASTER-REPORT.md`

```
أريد لحظة توقيع واحدة فقط (قاعدة البحث: واحدة ولا شيء غيرها) لموقع [نوع الموقع]:

نفّذ [الخيار A: خلفية shader توليدية — وصفة Alex Harri الكاملة:
fullscreen triangle بـ OGL + stacked simplex noise بسرعات متعاكسة + Y_SCALE=3
+ blur ديناميكي + gradient texture مبنية من ألوان الـ tokens في JS]
أو [الخيار C: جسيمات FBO بـ curl-noise مع morph عند السكرول].

إلزاميات التنفيذ من التقرير:
- WebGL بعد الـ hydration فقط (next/dynamic ssr:false) — لا شيء في first paint.
- DPR cap عند 2 + إيقاف الحلقة خارج الشاشة (IntersectionObserver) + fallback تدرج CSS/صورة.
- "reduce pixel count لا reduce features" على الجوال + نسخة reduced-motion كاملة.
- الألوان من tokens المشروع حصراً (لا أزرق/بنفسجي افتراضي).
- أرِني GLSL كاملاً مع تعليق لكل block (noise/stacking/uniforms) كي أفهمه وأعدّله.

ألوان المشروع: [hex]. المزاج: [هادئ/درامي/تقني]. الجوال أولوية: [نعم/لا].

## 6) طبقة التفاعلات الدقيقة (cursor / أزرار / حالات)

**ملفات:** `AGENT-INSTRUCTIONS.md` + `07-micro-interactions.md`

```
أضف طبقة تفاعلات دقيقة "مستوى الفائزين" إلى موقعي وفق تقرير التفاعلات المرفق:

1. ثبّت نظام التوقيت في globals.css أولاً: --ease-out-expo: cubic-bezier(0.16,1,0.3,1)
   + --dur-fast/base/slow: 180/280/480ms + --ease-curtain: cubic-bezier(0.77,0,0.175,1)
   ثم استبدل كل ease/transition افتراضية في الكود الحالي.
2. مؤشر مخصص dot+ring: ring تلحق بـ lerp 0.15–0.2 + mix-blend-mode: difference على الحاوية
   + morph وlabel ("View"/"Drag") عبر [data-cursor] — تفعيل فقط عند (hover:hover) and (pointer:fine)
   واحترام reduced-motion.
3. زر CTA مغناطيسي واحد فقط: gsap.quickTo بـ strength 0.35 وclamp 12–16px
   + النص الداخلي بحركة معاكسة 0.15.
4. تسطير روابط scaleX من جهة القراءة بـ transform-origin معاكس للدخول/الخروج
   + :focus-visible بنفس الحركة [وفي RTL: الدخول من اليمين].
5. طبقة ديزني: active:scale 0.97 على العناصر القابلة للضغط + Follow-Through
   (الحاوية 0.28s والأبناء +0.06s) + tooltip/modal بفيزياء نوابض (200-400 stiffness).
6. راجع التقرير للقواعد الاستثنائية (linear للتلاشي، ease-in-out للسكون→السكون، spring للسحب).

لا تضف أي تأثير غير مذكور — هذه طبقة إحكام لا طبقة زخرفة.
```

## 8) تحسين الأداء إلى 60fps + Core Web Vitals

**ملفات:** `AGENT-INSTRUCTIONS.md` + `09-animation-stack-performance.md` + `QA-CHECKLISTS.md`

```
موقعي [المجلد] يعاني [مشكلة محددة: jank/بطء تحميل/layout shift...] .
طبّق هندسة الأداء من تقرير المنظومة المرفق:

1. قياس أولاً: حدد الأرقام الحالية (LCP/CLS/INP/وزن JS/fps) قبل أي تعديل — لا تخمين.
2. قواعد الحركة: انقل كل ما يتحرك إلى transform/opacity حصراً؛ ابحث عن أي top/left/width/height
   متحرك أو transition: all وأصلحه.
3. WebGL/Canvas: DPR cap 2 + إيقاف خارج الشاشة + تقليل الجسيمات على الجوال (reduce pixel count).
4. تحميل: next/dynamic للـ WebGL (ssr:false) + IO lazy-init بـ rootMargin 200px
   + content-visibility: auto للأقسام البعد الطية + خطوط next/font مع display: swap.
5. rAF واحدة مشتركة + will-change بمنطق JIT (يوضع قبل الحركة ويزال بعدها) + إزالة lagSmoothing عند Lenis.
6. أعد القياس بعد كل حزمة تعديلات وأعطني جدول قبل/بعد — الهدف: LCP<1.5s، CLS<0.05، INP<100ms، 60fps.

بيئة القياس المتاحة: [Lighthouse/DevTools/هاتف فعلي...]. الم/device الأضعف المستهدف: [مثلاً أندرويد متوسط].

## نصائح للاستخدام مع كل القوالب

- **السياق أولاً ثم الطلب:** أرسل `AGENT-INSTRUCTIONS.md` ثم التقرير ثم البرومبت — بهذا الترتيب.
- **المراحل لا القفز:** اطلب من الوكيل التوقف عند نهاية كل مرحلة لمراجعتك (خصوصاً المرحلة 0 — الهوية).
- **المرجع قبل الكلمة:** كلما أمكن أرفق لقطات مراجع تحبها — "النموذج يقلد المرجع أفضل مما يفهم الوصف".
- **عند النتائج المختلطة:** أشر للوكيل بإحالة محددة (تقرير 1-x، النتيجة N) بدل "اجعلها أفضل".
- **التحقق النهائي دائماً:** لا مشروع يكتمل دون تمرير `QA-CHECKLISTS.md`.
