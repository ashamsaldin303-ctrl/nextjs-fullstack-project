## 3) الميزة 1 — المؤشر المغناطيسي (Magnetic Cursor)

### المواصفة
مؤشر مخصص من طبقتين: **نقطة** صغيرة دقيقة تتبع الماوس فوراً، و**حلقة** أكبر تتبع بنعومة (lerp 0.15–0.25). عند اقتراب المؤشر من عنصر تفاعلي (زر/رابط/تبويب) ضمن نطاق جذب ~80px: تتمدد الحلقة وتنجذب بلطف نحو مركز العنصر، وتعود لحجمها عند الابتعاد.

### قواعد تنفيذ إلزامية
1. **أجهزة المؤشر الدقيق فقط**: يُرسم فقط عند `window.matchMedia('(pointer: fine)')` — لا يُرسم إطلاقاً على اللمس. لا تخفِ المؤشر الأصلي إلا ضمن `@media (pointer: fine)` ومَن ليس لديه reduced-motion؛ في كل الحالات الأخرى يبقى المؤشر الأصلي سليماً.
2. **reduced-motion**: عند تفعيله يُخفى المؤشر المخصص كلياً (الحركة تتبع الماوس = حركة) — يعود المؤشر الأصلي.
3. **صفر إعادة رسم React لكل إطار**: حركة rAF واحدة على مستوى التطبيق تعالج الطبقتين بتعديل مباشر للـ DOM عبر refs (`transform: translate3d(...)` + `will-change`). لا setState ولا framer-motion re-render في حلقة الحركة.
4. **Hydration-safe**: لا يُرسم في SSR — بعد mount فقط.
5. **كشف العناصر التفاعلية**: `data-cursor="magnet"` attribute صريح على الأزرار/الروابط الرئيسية (لا تعتمد على التخمين العام بـ `a, button` — سيلتقط عناصر لا تريدها). احرص على تغطية أزرار Hero وCTA والحاسبة والمحاكي على الأقل.
6. **لا يعطل الوصولية إطلاقاً**: `pointer-events: none` دائماً، `aria-hidden="true"`، لا يبتلع النقرات، لا يغطي focus-visible، z-index فوق المحتوى وتحت الـ Sheet/Dialog (أو فوقها — بشرط الشفافية وعدم التشويش؛ اختر ووثّق).
7. **RTL/LTR محايد بالتصميم** (الجذب نحو المركز لا جهة اتجاهية) — تحقق بصرياً في العربية والإنجليزية.

## 4) الميزة 2 — الحبيبات السينمائية (Film Grain)

طبقة noise خفيفة فوق كامل الصفحة تمنح عمقاً سينمائياً:
1. **التنفيذ**: SVG `feTurbulence` (مضمّنة كـ data-URI في CSS أو inline SVG واحدة) — بلا صور PNG خارجية وبلا canvas.
2. **الخصائص**: `position: fixed` · `inset: 0` · شفافية **3–4% كحد أقصى** (حفاظاً على تباين WCAG 4.5:1) · `pointer-events: none` · `aria-hidden="true"`.
3. **ثابتة غير متحركة** — الحبيبات المتحركة تُكلّف الأداء وتشتت. قرار تصميمي نهائي.
4. **نسخة واحدة** على مستوى التطبيق (في `[locale]/layout.tsx`) — لا تُكرّر لكل صفحة.
5. تُخفى عند الطباعة (`@media print`)، وتُبقى فوق الخلفيات دون إزعاج النصوص (اختبر القراءة على الفاتح والداكن).

## 5) الميزة 3 — Audio UX (أصوات اصطناعية فائقة النعومة)

### المواصفة
أصوات مركّبة بالكامل عبر Web Audio API (oscillators + مغلفات gain) — **بلا أي ملفات صوتية** (وزن صفحة لا يتغير):
- **hover** على عناصر تفاعلية: نقطة خافتة جداً (sine، ~30ms، gain ≤ 0.04) مع خنق (throttle ≥ 60ms بين صوتين).
- **click**: نبضة ناعمة قصيرة (triangle، ~50–70ms، gain ≤ 0.1) بنغمة تنزل بلطف.
- **success** (نجاح إرسال الحاسبة / اكتمال المحاكي): أربيجيو صاعد قصير من 3 نغمات (90ms لكل نغمة).
- Master gain node واحد يتحكم بكل شيء (~0.6).

### قواعد إلزامية
1. **مطفأة افتراضاً** — لا صوت قبل موافقة المستخدم الصريحة (سياسات autoplay + ذوق عام).
2. **زر تبديل واضح بالزاوية** (أسفل-البداية، `fixed`، منطقي `start-4 bottom-4`) بأيقونة سماعة/كتم، مع `aria-label` مترجم (`footer` أو `common` namespace): «تشغيل المؤثرات الصوتية / Enable sound effects» + حالة `aria-pressed`.
3. **التفضيل في localStorage** (`elyra:sound`) — يُقرأ بعد mount فقط (hydration-safe).
4. **AudioContext يُنشأ كسولاً عند أول إيماءة مستخدم** بعد التفعيل، مع `resume()` عند الحاجة (سياسات المتصفحات).
5. **لا صوت مع التنقل بلوحة المفاتيح** ولا مع قارئات الشاشة — الأصوات لتفاعلات المؤشر فقط، ولا تعطل أو تعترض أي حدث.
6. مستقل عن reduced-motion (الصوت ليس حركة — لكنه opt-in أصلاً فلا تداخل).
7. أي شيء يعطل فشلاً هادئاً (صمتاً) — لا console errors.

## 6) إثراء المحتوى (كل شيء عبر i18n باللغتين)

1. **`/work`**: وسّع إلى **6 مشاريع** متنوعة الصناعات (تجارة إلكترونية، عقارات، تعليم، مطاعم، SaaS، وكالة إبداعية) — لكل مشروع: اسم واقعي، صناعة، قائمة خدمات، 2–3 مقياس نتيجة (مثل «+140% تحويلات»)، وvariant مناسب لـ before/after. المحتوى placeholder-واقعي قابل للاستبدال.
2. **`/about`**: فريق من 4 أعضاء (اسم، دور، سطر تعريفي — بلا صور أو بأفاتار حروف ملوّنة بـ BRAND_COLORS) + أرقام الوكالة (مشاريع، سنوات، أتمتة مُنفّذة، عملات سعيدة).
3. **الشهادات في الرئيسية**: 3–4 شهادات أعمق باسم/دور/شركة + اقتباس محدد النتائج.
4. **حصاد نثري أعمق** لصفحتي الخدمتين (فقرة إضافية لكل خدمة: «ماذا تشمل» و«كيف نعمل») — بدون اختراع خدمات جديدة.
5. **تكافؤ i18n 100%** — سكربت الباريتي يجب أن يمر صفر أخطاء، والمحتوى العربي **تأليف حقيقي لا ترجمة حرفية ركيكة** (نبرة تسويقية أنيقة).
6. لا تلمس بيانات `site-config.ts` placeholder — أضف قيم محتوى قابلة للترجمة في ملفات الرسائل.

## 7) الأداء وLighthouse + بنود P2

1. **الهدف: 90+ في الفئات الأربع** (Performance / Accessibility / Best Practices / SEO) لكل الصفحات باللغتين — شغّل Lighthouse فعلياً وسجّل النتائج (جدولاً في تقريرك) مع قبل/بعد لأي تعديل.
2. **JS المبدئي للأقسام الساكنة < 200KB** — الميزات الثلاث الجديدة يجب أن تكون شبه مجانية: المؤشر/الصوت مكونات client صغيرة، والـ Grain CSS خالص. قِس التغير عن المرحلة 1.
3. **P2-2 — فعّل React Compiler**: `reactCompiler: true` في next.config، وأصلح كل ما يكشفه (الآن القاعدة warning في lint — بعد التفعيل يجب أن يبقى 0/0).
4. **P2-3 — sitemap لكل لغة**: عناوين URL بديلة hreflang (ar/en/x-default) في `sitemap.ts` و`generateMetadata` — راجع توصية next-intl الرسمية للتنفيذ الصحيح.
5. افحص `next/font` (Inter + Cairo variable مع `display: swap`) وfont-loading وكشف أي CLS جديد سببه الميزات الحسية.

## 9) القواعد الإلزامية (مذكّرة — كاملة في برومبت المرحلة 1)

نفس القواعد دون استثناء: `await params` · `proxy.ts` لا `middleware.ts` · مكتبات >50KB بـ `ssr: false` ديناميكياً · تكافؤ i18n مع CI check · خصائص CSS منطقية فقط (`ms-/me-/ps-/pe-/start-/end-`) · Hydration-safe (كل منطق زمني/عميل بعد mount) · كل حركة لها بديل `prefers-reduced-motion` · **القواعد الصارمة في ESLint يجب أن تبقى مفعّلة ونتيجتها 0/0** (هذا الآن خط أحمر — أي تجاوز يُرفض عند المراجعة).
